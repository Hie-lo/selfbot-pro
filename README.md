# SelfBot Pro

ربات مدیریت سلف‌بات تلگرام: یک ربات کنترلی (python-telegram-bot) که اکانت‌های کاربران را
با Telethon و StringSession وصل می‌کند و قابلیت‌ها را به‌صورت پلاگین اجرا می‌کند.

## ساختار

```
main.py                 نقطه ورود ربات کنترلی
config.py               خواندن تنظیمات از .env + پلن‌ها و اطلاعات کارت
bot/
  handlers.py           هندلرهای ربات (منو، لاگین، ذخیره‌سازی)
  subscription.py       خرید اشتراک: انتخاب پلن، کارت به کارت، ارسال رسید
  admin.py              پنل ادمین: تایید درخواست‌ها، فعال‌سازی اشتراک، مدیریت مشتریان
  keyboards.py          کیبوردهای inline
  texts.py / i18n/      متن‌ها (fa)
  help_content.py       محتوای راهنما — منبع واحد برای ربات و `.راهنما`
  help_panel.py         راهنمای دکمه‌ای (منوی ربات + inline mode)
core/
  client_manager.py     مدیریت کلاینت‌های Telethon (login / reconnect)
  plugin_manager.py     لود و آنلود پلاگین‌ها به‌ازای هر کاربر
  security.py           اعتبارسنجی، rate limit، محاسبه انقضای اشتراک
  crypto.py             رمزنگاری session string با Fernet
  engine.py             استارت/استاپ سرور
  access.py             کنترل دسترسی زنده: انقضا، مسدودی، باطل شدن session (watchdog)
  runtime.py            اشتراک نمونه‌ی ربات بین موتور و ربات (اعلان‌ها، inline)
  instance_lock.py      قفل «فقط یک نمونه» (PostgreSQL advisory lock)
  governor.py           سقف سراسری کارهای سنگین + صف منصفانه
  metrics.py            اندازه‌گیری (RAM، تأخیر حلقه، نرخ‌ها) + پذیرش اکانت + /stats
  peers.py              دفترچه‌ی نام‌ها (بدون درخواست API برای هر پیام)
  pv_cache.py           کش مشترک ضدحذف/ضدویرایش + گاوصندوق مدیای رمزنگاری‌شده
  outbox.py             صف ارسال گزارش‌ها (مقاوم در برابر FloodWait)
tests/                  تست‌ها (بدون نیاز به .env/دیتابیس)
database/
  db.py                 کوئری‌های asyncpg
  models.py             اسکیمای PostgreSQL
plugins/                قابلیت‌های سلف‌بات (ضد حذف، تایم‌دار، بنر، تاس، ...)
```

### ⚠️ inline mode ربات را روشن کنید

راهنمای دکمه‌ای `.راهنما` داخل چت‌ها از طریق inline mode ربات کنترلی کار می‌کند
(اکانت کاربر خودش نمی‌تواند دکمه‌ی شیشه‌ای بفرستد). در @BotFather:
`/setinline` → انتخاب ربات → یک placeholder (مثلاً `help`).
اگر خاموش باشد، `.راهنما` به نسخه‌ی متنی برمی‌گردد و در لاگ هشدار داده می‌شود.

ساخت کلید رمزنگاری:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

## جریان خرید اشتراک

1. کاربر روی «💎 اشتراک» می‌زند و پلن را انتخاب می‌کند.
2. اطلاعات کارت (شماره کارت، صاحب کارت) نمایش داده می‌شود.
3. کاربر مبلغ را کارت به کارت می‌کند و «📸 ارسال عکس رسید» را می‌زند.
4. عکس رسید ضمیمه درخواست می‌شود و برای ادمین ارسال می‌گردد (با دکمه تایید/رد).
5. ادمین تایید می‌کند → پلن کاربر فعال/تمدید می‌شود و به کاربر اطلاع داده می‌شود.
6. درخواست‌های رد شده همراه علت به کاربر اعلام می‌شوند.

## فوروارد محتوا (دو روش)

**۱. کامند `.فوروارد` — برای کانال‌های لینک‌دار**

```
.فوروارد https://t.me/source به https://t.me/destination          # فوروارد واقعی
.فوروارد با آیدی https://t.me/source به https://t.me/destination  # با مشخصات فرستنده
```
لینک پیام هم قبول است (`https://t.me/source/123` یا `https://t.me/c/123456/789`).
هیچ پیامی در مبدأ یا مقصد ارسال نمی‌شود؛ کامند حذف و گزارش کامل در
**Saved Messages** ذخیره می‌شود.

**۲. دکمه «📥 فوروارد محتوا» در ربات — برای چت‌های بدون لینک**

گروه‌های خصوصی معمولی در تلگرام لینک ندارند و با کامند قابل ارجاع نیستند؛
این پنل لیست واقعی چت‌های اکانت را از خود تلگرام می‌خواند:

۱. انتخاب **چت مبدأ** از لیست (فیلتر «فقط کانال و گروه» + جستجو با نام)
۲. انتخاب **چت مقصد** از همان لیست، یا `Saved Messages`، یا ورود دستی
   لینک/`@username`/آیدی عددی
۳. تنظیمات: تعداد پیام (۱۰۰ تا همه)، سه حالت ارسال، فقط مدیا
۴. شروع + نوار پیشرفت + دکمه توقف در میانه کار

ورودی‌های قابل قبول (هم در کامند و هم در ورود دستی):

| ورودی | نمونه |
|---|---|
| یوزرنیم | `@channel` |
| آیدی عددی | `-1001234567890` |
| لینک کانال / پیام | `t.me/name` · `t.me/name/123` · `t.me/c/123/456` |
| **لینک دعوت گروه خصوصی** | `t.me/+AbCdEfGhIj` · `t.me/joinchat/AbCdEfGhIj` |

گروه‌های خصوصی که لینک عمومی ندارند هم از لیست چت‌های اکانت قابل انتخاب‌اند.
اگر لینک دعوت به گروهی باشد که اکانت **عضو نیست**، ربات توضیح می‌دهد و برای
عضویت تایید صریح می‌گیرد (عضویت برای اعضای گروه قابل مشاهده است).

نکات:
- **هیچ پیامی به چت مبدأ ارسال نمی‌شود** و پیام‌ها «خوانده‌شده» نمی‌شوند.
- گزارش فقط در چت ربات است (در حالت کامند: Saved Messages).
- کانال‌های محافظت‌شده خودکار به حالت «کپی» سوییچ می‌شوند.
- برای فوروارد به یک کانال، اکانت باید در آن ادمین باشد.
- یک فوروارد همزمان برای هر کاربر؛ سقف ۶ بار در ۱۰ دقیقه.

### فورواردهای بزرگ (هزاران پیام)

فوروارد در دسته‌های کوچک انجام می‌شود و در برابر محدودیت تلگرام مقاوم است:

- **هیچ سقفی روی تعداد پیام نیست** — job تا پایان می‌رود.
- اگر تلگرام `FloodWait` بدهد (حتی چند ساعت)، job **خواب می‌رود و خودش ادامه
  می‌دهد**؛ گزارش هم شمارش معکوس را نشان می‌دهد. هرگز نیمه‌کاره رها نمی‌شود.
- **پیشرفت روی سرور ذخیره می‌شود** (`forward_jobs`): اگر سرور ری‌استارت شود یا
  برق برود، از همان پیامی که مانده ادامه می‌دهد — بدون ارسال تکراری.
- دکمه **⏹ توقف (قابل ادامه)** و **▶️ ادامه فوروارد** برای کنترل دستی.
- **فوروارد گیرکرده:** اگر ردیفی «در حال اجرا» بماند ولی هیچ فورواردی واقعاً
  فعال نباشد (کرش/ری‌استارت)، ربات به‌جای پیام بن‌بست، خلاصه‌ی همان ردیف و
  دو گزینه نشان می‌دهد: **▶️ ادامه‌ی همان** یا **🔓 بستن و شروع فوروارد جدید**.
  در چت هم `.فوروارد بستن` همان کار را می‌کند.
  ردیف‌های مرده‌ی قدیمی (بیش از ۲ دقیقه بی‌فعالیت و بدون موتور اجرا) خودکار
  آزاد می‌شوند و هنگام بالا آمدن سرور، ردیف‌های بی‌صاحب خطا خورده و قفل
  شروع‌های بعدی را نمی‌گیرند.
- سرعت از `.env` قابل تنظیم است:

### ⚡ سرعت

سرعت با «پریست» انتخاب می‌شود (در پنل: دکمه‌ی **⚡ سرعت**):

| پریست | فاصله‌ی پیام‌ها | همزمانی | توضیح |
|---|---|---|---|
| 🐢 محتاط | 0.8s | 1 | برای اکانت‌های تازه یا حساس |
| ⚖️ متعادل (پیش‌فرض) | 0.2s | 1 | ترتیب دقیق حفظ می‌شود |
| 🚀 سریع | 0.08s | 2 | حدود ۲ برابر متعادل |
| 🔥 حداکثری | 0s | 4 | ممکن است محدودیت زودتر بخورد |

موتور خودش را با بازخورد تلگرام تنظیم می‌کند (`core/pacing.py`):
`FloodWait` خورد → فاصله‌ها چند برابر می‌شود؛ چند پیام بی‌مشکل رفت → کم‌کم
تندتر می‌شود (تا کف همان پریست). پس لازم نیست دستی وسواس کنی.

اندازه‌گیری واقعی (۸۰ پیام، تأخیر شبکه ۲۰ms):

| | قبل | متعادل | سریع |
|---|---|---|---|
| هر پیام | 925ms | **209ms** | 49ms |
| پیام در ثانیه | 1.1 | **4.8** | 20.5 |

یعنی متعادل ≈۴ برابر تنظیمات قبلی سریع‌تر است. تخمین ۴۵٬۰۰۰ پیام (فقط مکث،
بدون زمان شبکه و بدون محدودیت تلگرام): محتاط ≈۱۰ ساعت · متعادل ≈۲.۵ ساعت ·
سریع ≈۰.۵ ساعت.

⚠️ سقف واقعی سرعت را **خود تلگرام** تعیین می‌کند (FloodWait). با هر محدودیت،
job خودکار عقب‌نشینی می‌کند، منتظر می‌ماند و بعد ادامه می‌دهد — طول کل کار
بیشتر تابع محدودیت‌های تلگرام است تا تنظیمات ما. اکانت‌های پریمیوم معمولاً
سقف بالاتری دارند.

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `FORWARD_SPEED` | balanced | پریست سرعت: safe / balanced / fast / max |
| `FORWARD_CONCURRENCY` | 0 | چند پیام همزمان (۰ = از پریست) |
| `FORWARD_MSG_PAUSE` | — | (قدیمی/اختیاری) فاصله دستی پیام‌ها؛ اگر کمی کند باشد هشدار می‌دهد |
| `FORWARD_BATCH_SIZE` | 20 | تعداد پیام در هر دسته‌ی خواندن |
| `FORWARD_BATCH_PAUSE` | 1.0 | مکث بین دسته‌ها (فقط مسیرهای فوروارد واقعی) |
| `FORWARD_CACHE_BATCH` | 100 | تعداد پیام در هر خواندنِ فاز جمع‌آوری |
| `FORWARD_CACHE_PAUSE` | 0.15 | مکث بین دسته‌های جمع‌آوری (ثانیه) |
| `FORWARD_MAX_FLOOD_WAIT` | 86400 | سقف انتظار برای FloodWait |
| `FORWARD_CACHE_MODE` | 1 | اول همه پیام‌ها روی سرور ذخیره، بعد ارسال |
| `FORWARD_CACHE_CAPTURE_MEDIA` | 0 | دانلود مدیا و ذخیره روی دیسک سرور |
| `FORWARD_CACHE_MAX_GB` | 5 | سقف فضای دیسک برای کش مدیا |
| `FORWARD_CACHE_MEDIA_MAX_MB` | 100 | سقف حجم هر فایل مدیا در کش |

### 🗄 حالت کش — مقاوم در برابر قطع دسترسی

«اگر وسط فوروارد از کانال یا گروه بیرونم بیندازند، همه‌چیز خراب می‌شود؟»
نه — با حالت کش (پیش‌فرض روشن):

1. **فاز جمع‌آوری:** تمام پیام‌های مبدأ (به ترتیب و بدون ارسال چیزی به مبدأ)
   موقتاً روی سرور ذخیره می‌شوند — متن، فرستنده، تاریخ و لینک پیام.
2. **فاز ارسال:** پیام‌ها از روی ذخیره‌ی سرور به مقصد ارسال می‌شوند.

نتیجه: اگر وسط کار **اخراج شوید، کانال را پاک کنند یا خصوصی شود**، آنچه
جمع‌آوری شده از دست نمی‌رود و ارسال ادامه می‌یابد. اگر سرور ری‌استارت شود،
هر دو فاز خودکار ادامه پیدا می‌کنند.

| | زنده (بدون کش) | کش روی سرور |
|---|---|---|
| سرعت شروع | فوری | یک فاز اضافه اول کار |
| قطع دسترسی وسط کار | توقف | ✅ ارسال ادامه می‌یابد |
| مصرف فضا | صفر | چند ده بایت تا چند مگا بایت به‌ازای هر پیام |

- وقتی `FORWARD_CACHE_CAPTURE_MEDIA=1` باشد، فایل‌های مدیا هم روی دیسک
  سرور ذخیره می‌شوند (برای وقتی که مبدأ از بین رفته باشد). در غیر این‌صورت
  مدیا با «مرجع تلگرام» ارسال می‌شود که فضا نمی‌خورد.
- کش **موقت** است: با پایان کار، همه ردیف‌ها و فایل‌های کش پاک می‌شوند.
- در پنل ربات دو دکمه‌ی «🗄 ذخیره روی سرور» و «🖼 کش مدیا» قابل تغییرند.

### 🔒 استیکر و گیف در Recents (مهم)

در Telethon اگر مدیا «مرجع» باشد (از خود تلگرام بیاید و دانلود نشود)،
پارامتر `force_document` **نادیده گرفته می‌شود** و سرور همان استیکر/گیف را
می‌فرستد → به لیست «استیکرهای اخیر / گیف‌ها» اضافه می‌شود. پس:

- در همه‌ی حالت‌ها (جز `off`) بعد از هر ارسال، استیکر/گیف با
  `SaveRecentSticker(unsave=True)` و `SaveGif(unsave=True)` از Recents پاک می‌شود.
- اگر پاسخ تلگرام نوع مدیا را برنگرداند، از مرجع ذخیره‌شده (id/hash/file_reference)
  در دیتابیس استفاده می‌شود — پس در حالت کش هم لیست تمیز می‌ماند.

## مشخصات فرستنده (کی می‌گه، اهل کجاست)

یکی از سه حالت ارسال، «🏷 کپی با مشخصات فرستنده» است (پیش‌فرض پنل):
روی هر پیام، یک هدر با اطلاعات کامل درج می‌شود.

```
📥 از: گروه خانواده (-1001234567890)
👤 فرستنده: علی رضایی — @ali (123456789)
🕒 2026-09-22 14:22 (UTC)
🔗 https://t.me/c/1234567890/55
──────────────
متن اصلی پیام
```

- شناسه فرستنده به ترتیب اولویت: `@username` → آیدی عددی → نام
- لینک پیام: `t.me/<username>/<id>` برای چت‌های عمومی،
  `t.me/c/<id>/<msg>` برای خصوصی‌ها، `tg://openmessage` برای پیوی
- کپشن‌ها و متن‌ها خودکار به محدودیت تلگرام (۱۰۲۴ / ۴۰۹۶) کوتاه می‌شوند
- در این حالت پیام‌ها «کپی» می‌شوند (برچسب Forwarded ندارند)

## تمیز نگه داشتن Recents (استیکر و گیف)

تلگرام هر **استیکر** یا **گیف** که اکانت بفرستد را به لیست «استیکرهای اخیر»
و «گیف‌های ذخیره‌شده» اضافه می‌کند. ربات این را مدیریت می‌کند:

| مقدار `CLEAN_RECENTS_MODE` | رفتار |
|---|---|
| `document` (پیش‌فرض) | استیکر/گیف به‌صورت فایل ارسال می‌شود → هیچ‌وقت به Recents اضافه نمی‌شود. حتی در «فوروارد واقعی» هم استیکر/گیف به‌جای فوروارد شدن، به‌صورت فایل ارسال می‌شود |
| `cleanup` | استیکر/گیف واقعی ارسال می‌شود و سپس با `SaveRecentSticker(unsave)` و `SaveGif(unsave)` از Recents حذف می‌شود |
| `off` | رفتار قبلی (ممکن است Recents را پر کند) |

این محافظت روی این مسیرها اعمال می‌شود: ضد حذف، مانیتور کانال، ذخیره از لینک،
تایم‌دار، فوروارد محتوا، تبدیل استیکر.

پاکسازی لیست فعلی:
- از ربات: `📂 ذخیره‌سازی` → `🧹 پاکسازی استیکرهای Recent`
- از چت خودت: `.recents`

## 🔐 کنترل دسترسی زنده

`core/access.py` مرجع واحد تصمیم‌گیری درباره‌ی فعال بودن سلف‌بات هر کاربر است:

| رویداد | نتیجه |
|---|---|
| پایان اشتراک (حین اجرا یا هنگام ری‌استارت) | ⏸ معلق: پلاگین‌ها + فوروارد متوقف، اتصال قطع، session حفظ، اعلان به کاربر |
| تمدید / تایید رسید / `/activate` / فعال‌سازی دستی ادمین | ▶️ خودکار دوباره وصل و پلاگین‌ها لود می‌شوند |
| لغو اشتراک توسط ادمین | ⏸ فوری معلق |
| مسدودسازی | ⏸ فوری معلق + کاربر هیچ هندلری در ربات اجرا نمی‌کند؛ رفع مسدودی → برگشت |
| خروج session از Devices تلگرام | 🔴 revoked + اعلان؛ «اتصال اکانت» دوباره باز می‌شود |
| خطای شبکه هنگام اتصال | ⏸ معلق (offline) و تلاش دوباره در هر دور — session باطل علامت نمی‌خورد |
| ظرفیت سرور پر | ⏸ معلق (capacity) تا جا باز شود |
| `.روشن` بدون اشتراک | رد می‌شود (چک داخل `enable_plugin` هم هست) |

«🔌 قطع اکانت» حالا `log_out` واقعی انجام می‌دهد و session روی تلگرام هم باطل می‌شود.

## ⚡ کارایی و ظرفیت (بدون زیرساخت اضافه)

همه‌چیز داخل همین یک پروسه و با همین PostgreSQL — بدون Redis/صف خارجی.

| بخش | کار |
|---|---|
| `core/instance_lock.py` | advisory lock پستگرس: نمونه‌ی دوم اجرا نمی‌شود (جلوگیری از `AUTH_KEY_DUPLICATED` و باطل شدن همه‌ی sessionها)؛ اگر قفل وسط کار از دست برود و نمونه‌ی دیگری آن را بگیرد، این نمونه فوراً همه را قطع می‌کند |
| `core/governor.py` | سقف سراسری کارهای سنگین (فوروارد، ffmpeg، دانلود، کش مدیا) با صف منصفانه؛ پیام پیشرفت فوروارد «در صف (نفر N)» نشان می‌دهد؛ FloodWait طولانی ظرفیت را موقتاً آزاد می‌کند |
| `core/metrics.py` | تأخیر حلقه، RAM (با در نظر گرفتن محدودیت Docker/cgroup)، نرخ‌ها؛ پذیرش اکانت جدید بر اساس منابع واقعی؛ دستور ادمین `/stats` |
| `core/peers.py` | دفترچه‌ی نام‌ها: صفر درخواست API برای هر پیام (قبلاً تا ۴ درخواست) |
| `core/pv_cache.py` | کش مشترک ضدحذف/ضدویرایش با سقف حجم و سن + گاوصندوق مدیای رمزنگاری‌شده (AES-GCM، کلید جدا برای هر اکانت) |
| `core/outbox.py` | صف ارسال گزارش‌ها با فاصله و صبر واقعی روی FloodWait |

روشن شدن: اکانت‌ها موازی (با سقف) وصل می‌شوند. `cryptg` و `uvloop` (در requirements)
رمزنگاری و حلقه‌ی asyncio را سریع‌تر می‌کنند؛ نبودشان مشکلی ایجاد نمی‌کند.
لاگ‌ها چرخشی‌اند (`LOG_MAX_MB` × `LOG_BACKUPS`).

## 📖 راهنما (قانون نگهداری)

محتوای راهنما فقط در `bot/help_content.py` است و هر دو مسیر (دکمه «📖 راهنما»
در ربات و `.راهنما` در چت‌ها) از آن می‌خوانند. **هر قابلیت یا دستوری که اضافه
یا تغییر می‌کند، باید همان‌جا هم به‌روز شود** (بخش مربوطه + `COMMANDS`).

```bash
python tests/test_help_coverage.py   # هر دستور plugins/ باید در راهنما باشد
python tests/test_access.py          # سناریوهای انقضا/مسدودی/revoke
python tests/test_pv_cache.py        # ضدحذف/ضدویرایش: قالب، حذف دسته‌ای، گاوصندوق، سقف حافظه
python tests/test_capacity.py        # صف منابع، پذیرش، قفل تک‌نمونه، روشن شدن موازی
# یا: python -m pytest tests/
```

## پنل ادمین (دکمه «🛠 پنل ادمین» در منوی اصلی)

- **📥 درخواست‌های اشتراک:** لیست درخواست‌های در انتظار + عکس رسید، تایید/رد
- **👥 مدیریت مشتریان:** لیست کاربران، فعال‌سازی دستی پلن‌ها، لغو اشتراک، مسدود/رفع مسدودی
- **📊 آمار:** تعداد کاربران، اشتراک‌های فعال، اکانت‌های متصل، درخواست‌های در انتظار

دستورات ادمین در چت: `/activate <telegram_id> <days>`، `/users` و `/stats` (وضعیت منابع سرور)
دستور کاربر: `/help` (راهنمای دکمه‌ای)

## نکته امنیتی

session string کاربران با `ENCRYPTION_KEY` رمزنگاری می‌شود و هش شماره تلفن
HMAC کلیددار است (با همین کلید)؛ این کلید و فایل `.env` را
هرگز commit یا به اشتراک نگذارید. این پروژه به‌صورت سلف‌بات کار می‌کند و استفاده از آن
با قوانین تلگرام هم‌راستا نیست؛ مسئولیت استفاده بر عهده کاربر است.
